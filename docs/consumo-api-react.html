5.1 Objetivos da aula

Ao final desta aula, o(a) aluno(a) deve ser capaz de:

  1. Explicar o modelo cliente-servidor e o ciclo requisição → resposta do protocolo HTTP (métodos, status, cabeçalhos e corpo).
  2. Ler a documentação de uma API REST e identificar seus endpoints, parâmetros e formato de resposta em JSON.
  3. Entender o que é CORS e por que ele determina se uma API pode ser consumida diretamente pelo navegador.
  4. Usar a Fetch API com async/await para buscar (GET) e enviar (POST) dados JSON, tratando corretamente erros HTTP e erros de rede.
  5. Integrar requisições a componentes React com useState, useEffect, useReducer e Context API, exibindo estados de carregando, erro, vazio e sucesso.
  6. Validar campos obrigatórios antes do envio e exibir mensagens de erro depois do envio (respostas da API).
  7. Gerar o pacote de deployment (npm run build) e publicar a aplicação em um servidor web.

Por que este capítulo? Ele prepara diretamente para o Projeto 1 — ReactJS. Ao final (Seção 5.16), há uma tabela que relaciona cada critério de avaliação do projeto à seção deste capítulo que o explica.

5.2 Onde estamos no desenvolvimento full stack?

No Capítulo 4, a home page da AutoStore exibia veículos a partir de um array fixo (src/data/veiculos.js). Em uma aplicação real, esses dados não moram no front-end: eles ficam em um servidor, normalmente guardados em um banco de dados, e são entregues ao navegador por meio de uma API.

┌──────────────────────────┐    1. Requisição HTTP (GET/POST...)    ┌────────────────────────┐
│  NAVEGADOR (cliente)     │ ─────────────────────────────────────► │  SERVIDOR (API)        │
│                          │    ex.: GET /products/search?q=civic   │                        │
│  React (SPA)             │                                        │  Regras de negócio     │
│  - componentes           │    2. Resposta HTTP                    │  Banco de dados        │
│  - estado (state)        │ ◄───────────────────────────────────── │                        │
│  - fetch / AJAX          │    status 200 + corpo em JSON          │                        │
└──────────────────────────┘                                        └────────────────────────┘
        FRONT-END                                                          BACK-END
     (Projeto 1)                                                        (Projeto 2)

Neste capítulo, construímos somente o lado esquerdo (front-end), consumindo uma API que já existe. No Projeto 2, vocês construirão também o lado direito (back-end com Node/Express).

5.2.1 SPA e AJAX — revisão rápida

  • SPA (Single Page Application): a aplicação é carregada uma única vez (um único index.html). A partir daí, o JavaScript atualiza partes da tela sem recarregar a página.
  • AJAX (Asynchronous JavaScript and XML): técnica de fazer requisições HTTP em segundo plano, sem bloquear a interface. Apesar do “XML” no nome, hoje o formato dominante é o JSON, e a ferramenta moderna para isso no navegador é a Fetch API (fetch).

É a combinação das duas coisas que o Projeto 1 pede: uma SPA em React que usa AJAX para conversar com uma API JSON.

5.3 Conceitos fundamentais de HTTP

O HTTP (HyperText Transfer Protocol) é o protocolo de comunicação da Web. Toda conversa é composta de uma requisição (enviada pelo cliente) e uma resposta (devolvida pelo servidor). É um protocolo sem estado (stateless): cada requisição é independente e deve carregar tudo o que o servidor precisa para respondê-la.

5.3.1 Anatomia de uma requisição e de uma resposta

POST /products/add HTTP/1.1                     ← método, caminho e versão
Host: dummyjson.com                             ← cabeçalhos (headers)
Content-Type: application/json
Accept: application/json

{"title": "Opala 1978", "price": 98000}         ← corpo (body) — opcional
HTTP/1.1 201 Created                            ← versão, código de status e texto
Content-Type: application/json; charset=utf-8   ← cabeçalhos
Access-Control-Allow-Origin: *

{"id": 195, "title": "Opala 1978", "price": 98000}   ← corpo da resposta
Table 5.1: Partes de uma mensagem HTTP
Parte Na requisição Na resposta
Linha inicial Método + caminho (ex.: GET /products) Código de status (ex.: 200 OK)
Cabeçalhos (headers) Metadados: tipo do corpo enviado (Content-Type), formato aceito (Accept), credenciais (Authorization) Metadados: tipo do corpo devolvido, regras de CORS, cache
Corpo (body) Dados enviados (em POST/PUT/PATCH) Dados devolvidos (em geral, JSON)

5.3.2 Métodos HTTP (verbos)

Table 5.2: Principais métodos HTTP e seu uso em APIs REST
Método Intenção Tem corpo na requisição? Exemplo
GET Ler um recurso ou uma lista Não GET /products/1
POST Criar um novo recurso Sim POST /products/add
PUT Substituir um recurso inteiro Sim PUT /products/1
PATCH Alterar parcialmente um recurso Sim PATCH /products/1
DELETE Remover um recurso Normalmente não DELETE /products/1

Os quatro verbos centrais correspondem ao famoso CRUD (Create = POST, Read = GET, Update = PUT/PATCH, Delete = DELETE).

5.3.3 Códigos de status

O código de status é a primeira coisa que o front-end deve verificar em uma resposta. Ele é organizado em faixas:

Table 5.3: Faixas e códigos de status HTTP mais comuns
Código Significado O que o front-end deve fazer
200 OK Sucesso Usar os dados do corpo.
201 Created Recurso criado (resposta típica de POST) Mostrar mensagem de sucesso; usar o objeto devolvido (com id).
204 No Content Sucesso, sem corpo Não chamar response.json() (não há JSON para ler).
400 Bad Request Dados enviados inválidos Exibir a mensagem de erro devolvida pela API.
401 Unauthorized / 403 Forbidden Falta autenticação / sem permissão Pedir login ou informar falta de acesso.
404 Not Found Recurso ou endpoint inexistente Informar “não encontrado”; conferir a URL.
422 Unprocessable Entity Dados com formato válido, mas regra violada Exibir as mensagens de validação do servidor.
429 Too Many Requests Limite de requisições excedido Pedir para tentar novamente mais tarde.
500–503 Erro no servidor Mensagem genérica: “serviço indisponível, tente mais tarde”.

Regra prática: 2xx = sucesso, 4xx = o cliente errou algo, 5xx = o servidor falhou.

5.4 APIs REST, endpoints e parâmetros

Uma API (Application Programming Interface) é um “contrato” que define como um programa pode pedir dados ou serviços a outro. Uma API Web faz isso por HTTP. Quando ela segue o estilo arquitetural REST, os dados são organizados em recursos (produtos, usuários, filmes…), identificados por URLs, e manipulados com os métodos HTTP da Tabela 5.2.

  • URL base: o endereço comum a todas as rotas da API (ex.: https://dummyjson.com).
  • Endpoint: a combinação de método + caminho que realiza uma operação (ex.: GET /products/search).
  • Recurso: a “coisa” manipulada (ex.: products).

5.4.1 Anatomia de uma URL de requisição

https://dummyjson.com/products/category/vehicle?limit=10&sortBy=price&order=asc
└─┬─┘   └─────┬─────┘└──────────┬────────────┘ └──────────────┬──────────────┘
protocolo   domínio        caminho (path)            query string (parâmetros)
                        └ "vehicle" é um              pares chave=valor
                          parâmetro de rota            separados por &
Table 5.4: Formas de enviar parâmetros para uma API
Tipo Onde vai Exemplo Uso típico
Parâmetro de rota (path param) Dentro do caminho /products/1, /products/category/vehicle Identificar um recurso ou grupo.
Query string (query param) Após o ?, em pares chave=valor ?q=civic&limit=10 Buscas, filtros, ordenação e paginação.
Corpo (body) No corpo da requisição, em JSON {"title": "Opala"} Enviar dados para criar/alterar (POST, PUT, PATCH).
Cabeçalho Nos headers Authorization: Bearer <token> Credenciais e metadados.

Para o Projeto 1: o critério “busca com envio de parâmetros para a API JSON” é atendido, em geral, montando uma query string (ou um parâmetro de rota) com os valores que o usuário digitou em um formulário. Veremos como fazer isso com segurança usando URLSearchParams na Seção 5.11.3.

5.5 JSON: o formato de troca de dados

JSON (JavaScript Object Notation) é um formato de texto para representar dados estruturados. Sua sintaxe foi inspirada nos objetos literais do JavaScript, mas JSON não é JavaScript: é uma string com regras próprias, que qualquer linguagem (Python, Java, C#…) consegue ler e escrever. É por isso que ele é o formato padrão entre front-end e back-end.

{
  "products": [
    {
      "id": 1,
      "title": "Civic Si",
      "price": 189000,
      "inStock": true,
      "tags": ["esportivo", "sedan"],
      "dimensions": { "width": 1.8, "height": 1.4 },
      "discount": null
    }
  ],
  "total": 1,
  "skip": 0,
  "limit": 10
}
Table 5.5: Diferenças entre JSON e um objeto JavaScript
Regra JSON Objeto JavaScript
Chaves Sempre entre aspas duplas: "title" Aspas opcionais: title
Strings Apenas aspas duplas Aspas simples, duplas ou crase
Tipos permitidos string, número, true/false, null, objeto, array Qualquer valor, inclusive funções, undefined, Date
Vírgula após o último item Proibida Permitida
Comentários Não existem Permitidos

5.5.1 Convertendo entre JSON e JavaScript

// Objeto JavaScript → texto JSON (para ENVIAR à API)
const veiculo = { title: 'Opala 1978', price: 98000 };
const texto = JSON.stringify(veiculo);
// '{"title":"Opala 1978","price":98000}'

// Texto JSON → objeto JavaScript (ao RECEBER da API)
const objeto = JSON.parse('{"title":"Opala 1978","price":98000}');
console.log(objeto.title); // "Opala 1978"

Com a Fetch API, a conversão de entrada é feita por await resposta.json() (que faz o JSON.parse por você); a de saída continua sendo feita com JSON.stringify(...) no corpo da requisição.

5.6 CORS: por que algumas APIs “não funcionam” no navegador

Por segurança, o navegador aplica a política de mesma origem (same-origin policy): um script carregado de http://localhost:5173 não pode, por padrão, ler respostas vindas de outra origem (outro domínio, porta ou protocolo), como https://dummyjson.com.

O CORS (Cross-Origin Resource Sharing) é o mecanismo que o servidor usa para liberar esse acesso, enviando cabeçalhos como:

Access-Control-Allow-Origin: *

Se a API não enviar esse cabeçalho, a requisição até chega ao servidor, mas o navegador bloqueia a leitura da resposta, e o console mostra algo como:

Access to fetch at 'https://api.exemplo.com/...' from origin 'http://localhost:5173'
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present...

Pontos importantes:

  • CORS não se resolve no React. É uma configuração do servidor. Se a API escolhida não libera CORS, troque de API (ou, no Projeto 2, crie seu próprio back-end que faça a intermediação).
  • A mesma URL pode funcionar no Postman, no curl ou digitada na barra do navegador — e falhar no fetch. Isso acontece porque essas ferramentas não aplicam a política de mesma origem.
  • Requisições com corpo JSON (Content-Type: application/json) ou com cabeçalhos personalizados disparam uma requisição prévia do tipo OPTIONS (preflight), que você verá na aba Network. Isso é normal. Por isso, só envie Content-Type: application/json quando de fato houver corpo.

5.7 Explorando uma API antes de programar

Antes de escrever uma linha de React, teste a API manualmente. Isso evita horas depurando um componente quando o problema é, na verdade, a URL ou o formato do JSON.

Neste capítulo usaremos a DummyJSON (https://dummyjson.com), uma API pública e gratuita, com CORS liberado, que responde e recebe JSON. Os endpoints que usaremos:

Table 5.7: Endpoints da DummyJSON usados no exemplo da aula
Método Endpoint Parâmetros Resposta
GET /products/category/vehicle limit, skip, select, sortBy, order { products: [...], total, skip, limit }
GET /products/search q (termo), limit, skip, select, sortBy, order { products: [...], total, skip, limit }
GET /products/category-list — Array de strings com as categorias
POST /products/add Corpo JSON com os dados do produto Objeto criado, com id gerado

Importante: a DummyJSON simula a criação. O POST responde como se tivesse salvo o produto (devolvendo um id), mas o dado não é persistido no servidor. Isso é comum em APIs de teste (como a JSONPlaceholder) e é suficiente para aprender o fluxo de envio.

5.7.1 Três formas de testar

  1. Barra de endereços do navegador (somente GET): abra https://dummyjson.com/products/search?q=phone&limit=2 e observe o JSON.
  2. Terminal com curl (GET e POST):
# GET com parâmetros
curl "https://dummyjson.com/products/category/vehicle?limit=3&select=title,price"

# POST enviando JSON
curl -X POST "https://dummyjson.com/products/add" \
  -H "Content-Type: application/json" \
  -d '{"title": "Opala 1978", "price": 98000, "category": "vehicle"}'
  1. Ferramentas gráficas: extensão Thunder Client ou REST Client no VS Code, Postman ou Insomnia.

Anote, para a sua API: a URL base, os endpoints que usará, os parâmetros aceitos, o formato exato do JSON de resposta (em que chave está o array? como se chamam os campos?) e o formato das respostas de erro.

5.8 A Fetch API em detalhe

A função fetch(url, opcoes) faz uma requisição HTTP e retorna uma Promise que se resolve com um objeto Response. Como visto na revisão de Promises e async/await, usaremos a sintaxe async/await, mais legível.

5.8.1 GET — buscando dados

async function buscarVeiculos() {
  const resposta = await fetch('https://dummyjson.com/products/category/vehicle?limit=5');
  const dados = await resposta.json();   // converte o corpo JSON em objeto JS
  console.log(dados.products);           // array de veículos
}

São dois await: o primeiro espera a resposta chegar (cabeçalhos e status); o segundo espera o corpo ser lido e convertido.

5.8.2 POST — enviando dados

async function cadastrarVeiculo(veiculo) {
  const resposta = await fetch('https://dummyjson.com/products/add', {
    method: 'POST',                                   // 1. o método
    headers: { 'Content-Type': 'application/json' },  // 2. avisa que o corpo é JSON
    body: JSON.stringify(veiculo),                    // 3. o corpo, convertido em texto
  });
  return resposta.json();                             // objeto criado, com id
}

Os três itens numerados são o que diferencia um POST de um GET. Esquecer o Content-Type ou o JSON.stringify são os erros mais comuns: o servidor recebe um corpo que não consegue interpretar.

5.8.3 A armadilha: fetch não rejeita em erros HTTP

A Promise do fetch só é rejeitada (cai no catch) quando não há resposta: falta de internet, DNS inválido, bloqueio de CORS. Uma resposta 404 ou 500 é, para o fetch, uma resposta válida! Por isso, sempre verifique resposta.ok (que é true para status 200–299):

async function buscarVeiculoPorId(id) {
  try {
    const resposta = await fetch(`https://dummyjson.com/products/${id}`);

    if (!resposta.ok) {
      // A API respondeu, mas com erro (4xx/5xx). Muitas APIs mandam
      // uma mensagem explicativa no corpo, ex.: { "message": "..." }
      const corpo = await resposta.json().catch(() => null);
      throw new Error(corpo?.message ?? `Erro ${resposta.status}`);
    }

    return await resposta.json();
  } catch (erro) {
    // Chega aqui tanto o erro lançado acima quanto falhas de rede/CORS
    console.error('Falha na requisição:', erro.message);
    throw erro; // repassa para quem chamou decidir o que mostrar na tela
  }
}
Table 5.8: Tipos de erro ao consumir uma API
Situação Como o fetch se comporta Como detectar
Sucesso (2xx) Promise resolvida, resposta.ok === true —
Erro HTTP (4xx/5xx) Promise resolvida, resposta.ok === false if (!resposta.ok)
Sem rede, DNS, CORS Promise rejeitada com TypeError (“Failed to fetch”) try/catch
JSON malformado resposta.json() rejeita com SyntaxError try/catch
Requisição cancelada Promise rejeitada com AbortError erro.name === 'AbortError'

5.8.4 Montando a query string com URLSearchParams

Concatenar texto do usuário direto na URL é arriscado: espaços, acentos e caracteres como & ou ? quebram a requisição. O URLSearchParams faz a codificação (encoding) automaticamente:

const params = new URLSearchParams({ q: 'fusca & opala', limit: 10 });
console.log(params.toString());   // "q=fusca+%26+opala&limit=10"

fetch(`https://dummyjson.com/products/search?${params}`);

E o Axios? O Axios é uma biblioteca popular que faz o mesmo que o fetch, com algumas conveniências: converte JSON automaticamente e rejeita a Promise em respostas 4xx/5xx. Neste capítulo usamos o fetch porque ele é nativo do navegador e deixa os conceitos visíveis. Se o grupo quiser usar Axios, lembre-se de que toda biblioteca precisa de aprovação prévia do professor.

5.9 Requisições dentro de componentes React

5.9.1 Onde não colocar um fetch

Um componente React é uma função que pode ser executada muitas vezes (a cada mudança de estado ou de props). Um fetch escrito diretamente no corpo do componente seria disparado a cada renderização — e, se ele mudar o estado, causará uma nova renderização, um novo fetch… um laço infinito:

// ❌ ERRADO — laço infinito de requisições
function ListaVeiculos() {
  const [veiculos, setVeiculos] = useState([]);

  fetch('https://dummyjson.com/products/category/vehicle')
    .then((r) => r.json())
    .then((dados) => setVeiculos(dados.products)); // muda o estado → renderiza de novo → fetch de novo...

  return <ul>{veiculos.map((v) => <li key={v.id}>{v.title}</li>)}</ul>;
}

Existem dois lugares corretos para fazer requisições em React:

  1. Em um manipulador de evento (onSubmit, onClick): quando a requisição é consequência de uma ação do usuário — por exemplo, clicar em “Buscar” ou “Cadastrar”. É o caso mais comum no projeto.
  2. Em um useEffect: quando a requisição deve acontecer porque o componente apareceu na tela (ou porque algum valor mudou) — por exemplo, carregar a lista inicial de veículos ou as opções de um <select>.

5.9.2 O hook useEffect

useEffect(funcao, dependencias) executa funcao depois que o componente é desenhado na tela. O array de dependências controla quando ele roda de novo:

Table 5.9: Comportamento do useEffect conforme o array de dependências
Forma Quando executa
useEffect(fn) Após toda renderização (raramente é o que você quer).
useEffect(fn, []) Uma vez, quando o componente aparece (mount).
useEffect(fn, [categoria]) Quando aparece e sempre que categoria mudar.

A função passada ao useEffect não pode ser async diretamente (ela deve retornar nada ou uma função de limpeza, e não uma Promise). Por isso, declaramos uma função async dentro dele:

import { useEffect, useState } from 'react';

function ListaVeiculos() {
  const [veiculos, setVeiculos] = useState([]);
  const [carregando, setCarregando] = useState(true);
  const [erro, setErro] = useState(null);

  useEffect(() => {
    const controlador = new AbortController();          // permite cancelar a requisição

    async function carregar() {
      try {
        const resposta = await fetch(
          'https://dummyjson.com/products/category/vehicle',
          { signal: controlador.signal },
        );
        if (!resposta.ok) throw new Error(`Erro ${resposta.status}`);
        const dados = await resposta.json();
        setVeiculos(dados.products);
      } catch (e) {
        if (e.name !== 'AbortError') setErro(e.message); // cancelamento não é erro
      } finally {
        setCarregando(false);
      }
    }

    carregar();

    return () => controlador.abort();                    // limpeza: cancela se o componente sair da tela
  }, []);                                                // [] → executa uma vez

  if (carregando) return <p>Carregando...</p>;
  if (erro) return <p className="text-danger">Não foi possível carregar: {erro}</p>;
  if (veiculos.length === 0) return <p>Nenhum veículo encontrado.</p>;

  return (
    <ul>
      {veiculos.map((v) => <li key={v.id}>{v.title}</li>)}
    </ul>
  );
}

Por que a requisição aparece duas vezes no DevTools? Em modo de desenvolvimento, o <StrictMode> (presente no main.jsx do Vite) monta, desmonta e monta de novo cada componente, para ajudar a encontrar efeitos sem limpeza. Com o AbortController, a primeira requisição é cancelada e tudo funciona. Em produção (npm run build), isso não acontece.

5.9.3 Os quatro estados de uma tela que consome API

Toda interface que depende de uma requisição deve prever quatro situações. Esquecer qualquer uma delas é a causa mais comum de telas “em branco”:

Table 5.10: Estados de interface ao consumir uma API
Estado Condição O que exibir
Carregando Requisição em andamento Spinner ou texto “Carregando…”; desabilitar o botão de envio.
Erro Erro HTTP ou de rede Mensagem clara e, se possível, como resolver.
Vazio Sucesso, mas lista vazia “Nenhum resultado para termo”.
Sucesso Dados disponíveis Os dados renderizados com .map().

5.10 Organizando o estado global: Context API + useReducer

Quando o formulário de busca, a lista de resultados e o formulário de cadastro são componentes diferentes, eles precisam compartilhar os mesmos dados (a lista de veículos, o estado de carregamento, o erro). Passar tudo via props, nível a nível, gera o chamado prop drilling. A solução vista no material 06.1-react-context é a Context API:

                     <VeiculosProvider>   ← guarda o estado e as funções que chamam a API
                            │
         ┌──────────────────┼──────────────────┐
         ▼                  ▼                  ▼
    <FormBusca />   <ListaResultados />   <FormCadastro />
   (chama buscar)     (lê o estado)      (chama cadastrar)

Para gerenciar um estado com vários campos que mudam juntos (carregando + erro + dados), o hook useReducer é mais organizado que vários useState. Ele centraliza as transições de estado em uma função pura chamada reducer:

// (estado atual, ação) → novo estado
function reducer(estado, acao) {
  switch (acao.type) {
    case 'BUSCA_INICIOU': return { ...estado, carregando: true, erro: null };
    case 'BUSCA_SUCESSO': return { ...estado, carregando: false, produtos: acao.produtos };
    case 'BUSCA_ERRO':    return { ...estado, carregando: false, erro: acao.erro };
    default: throw new Error(`Ação desconhecida: ${acao.type}`);
  }
}

const [estado, dispatch] = useReducer(reducer, estadoInicial);
dispatch({ type: 'BUSCA_INICIOU' }); // "dispara" uma ação

Relação com o projeto: useReducer é uma das opções de hook da lista do Projeto 1 (junto com useMemo, useRef, memo, lazy, createPortal, react-redux, etc.). Usamos aqui como exemplo; o seu grupo deve implementar o hook/funcionalidade que escolheu e demonstrá-lo de forma significativa.

5.11.3 Passo 3 — Criar o contexto com o reducer e as funções da API

Este é o “coração” da aplicação. Leia com calma os comentários numerados.

// src/contexts/VeiculosContext.jsx
import { createContext, useCallback, useContext, useMemo, useReducer } from 'react';

// (1) URL base vinda do .env, com um valor padrão
const API_URL = import.meta.env.VITE_API_URL ?? 'https://dummyjson.com';

// (2) Somente os campos que a interface usa (menos dados trafegando)
const CAMPOS = 'id,title,brand,price,category,thumbnail';

// (3) Função genérica de requisição: trata JSON, erros HTTP e erros de rede
async function requisicao(caminho, opcoes = {}) {
  let resposta;
  try {
    resposta = await fetch(`${API_URL}${caminho}`, {
      ...opcoes,
      // Content-Type só quando há corpo (evita preflight desnecessário no GET)
      headers: opcoes.body ? { 'Content-Type': 'application/json' } : undefined,
    });
  } catch (erro) {
    if (erro.name === 'AbortError') throw erro;
    throw new Error('Não foi possível conectar à API. Verifique sua conexão.');
  }

  const dados = await resposta.json().catch(() => null);

  if (!resposta.ok) {
    throw new Error(dados?.message ?? `A API respondeu com erro ${resposta.status}.`);
  }
  return dados;
}

// (4) Estado inicial e reducer
const estadoInicial = {
  produtos: [],
  total: 0,
  carregando: false,
  erro: null,
  ultimaBusca: null, // termo da última busca realizada (null = carga inicial)
};

function veiculosReducer(estado, acao) {
  switch (acao.type) {
    case 'BUSCA_INICIOU':
      return { ...estado, carregando: true, erro: null };
    case 'BUSCA_SUCESSO':
      return {
        ...estado,
        carregando: false,
        produtos: acao.produtos,
        total: acao.total,
        ultimaBusca: acao.termo,
      };
    case 'BUSCA_ERRO':
      return { ...estado, carregando: false, erro: acao.erro, produtos: [], total: 0 };
    case 'VEICULO_ADICIONADO':
      return {
        ...estado,
        produtos: [acao.veiculo, ...estado.produtos],
        total: estado.total + 1,
      };
    default:
      throw new Error(`Ação desconhecida: ${acao.type}`);
  }
}

// (5) Criação do contexto
const VeiculosContext = createContext(null);

// (6) Provider: guarda o estado e expõe as operações
export function VeiculosProvider({ children }) {
  const [estado, dispatch] = useReducer(veiculosReducer, estadoInicial);

  // GET /products/category/vehicle — carga inicial
  const carregarVeiculos = useCallback(async (signal) => {
    dispatch({ type: 'BUSCA_INICIOU' });
    try {
      const params = new URLSearchParams({ limit: 12, select: CAMPOS });
      const dados = await requisicao(`/products/category/vehicle?${params}`, { signal });
      dispatch({ type: 'BUSCA_SUCESSO', produtos: dados.products, total: dados.total, termo: null });
    } catch (erro) {
      if (erro.name !== 'AbortError') dispatch({ type: 'BUSCA_ERRO', erro: erro.message });
    }
  }, []);

  // GET /products/search?q=...&sortBy=...&order=...&limit=... — busca com parâmetros
  const buscarVeiculos = useCallback(async ({ termo, ordenarPor, ordem, limite }) => {
    dispatch({ type: 'BUSCA_INICIOU' });
    try {
      const params = new URLSearchParams({ q: termo, limit: limite, select: CAMPOS });
      if (ordenarPor) {
        params.append('sortBy', ordenarPor);
        params.append('order', ordem);
      }
      const dados = await requisicao(`/products/search?${params}`);
      dispatch({ type: 'BUSCA_SUCESSO', produtos: dados.products, total: dados.total, termo });
    } catch (erro) {
      dispatch({ type: 'BUSCA_ERRO', erro: erro.message });
    }
  }, []);

  // GET /products/category-list — opções do <select> de categoria
  const listarCategorias = useCallback(
    (signal) => requisicao('/products/category-list', { signal }),
    [],
  );

  // POST /products/add — envia JSON e devolve o objeto criado
  const cadastrarVeiculo = useCallback(async (veiculo) => {
    const criado = await requisicao('/products/add', {
      method: 'POST',
      body: JSON.stringify(veiculo),
    });
    dispatch({ type: 'VEICULO_ADICIONADO', veiculo: criado });
    return criado; // o formulário usa o retorno para a mensagem de sucesso
  }, []);

  // (7) useMemo evita recriar o objeto a cada renderização do Provider
  const valor = useMemo(
    () => ({ ...estado, carregarVeiculos, buscarVeiculos, listarCategorias, cadastrarVeiculo }),
    [estado, carregarVeiculos, buscarVeiculos, listarCategorias, cadastrarVeiculo],
  );

  return <VeiculosContext.Provider value={valor}>{children}</VeiculosContext.Provider>;
}

// (8) Hook personalizado para consumir o contexto com segurança
// eslint-disable-next-line react-refresh/only-export-components
export function useVeiculos() {
  const contexto = useContext(VeiculosContext);
  if (!contexto) {
    throw new Error('useVeiculos deve ser usado dentro de <VeiculosProvider>.');
  }
  return contexto;
}

Observe a divisão de responsabilidades:

  • A função requisicao concentra todo o tratamento de erros (Tabela 5.8). Os demais trechos só precisam de try/catch.
  • As funções de busca não recebem nem devolvem JSX: elas só atualizam o estado com dispatch. Quem decide o que desenhar são os componentes.
  • cadastrarVeiculo relança o erro (não tem catch), porque quem deve mostrar a mensagem de erro do envio é o próprio formulário de cadastro.

5.11.5 Passo 5 — Formulário de busca com validação antes do envio

O formulário usa componentes controlados (vistos no material 05-react-events-states-props): o valor de cada campo mora no estado, e cada digitação atualiza esse estado.

// src/components/FormBusca.jsx
import { useState } from 'react';
import { useVeiculos } from '../contexts/VeiculosContext.jsx';

function validarBusca({ termo, limite }) {
  const erros = {};
  if (termo.trim() === '') {
    erros.termo = 'Informe um termo para a busca.';
  } else if (termo.trim().length < 2) {
    erros.termo = 'Digite pelo menos 2 caracteres.';
  }
  if (!Number.isInteger(limite) || limite < 1 || limite > 30) {
    erros.limite = 'Escolha entre 1 e 30 resultados.';
  }
  return erros;
}

function FormBusca() {
  const { buscarVeiculos, carregando } = useVeiculos();

  const [termo, setTermo] = useState('');
  const [ordenacao, setOrdenacao] = useState('');   // ex.: "price:asc"
  const [limite, setLimite] = useState(10);
  const [erros, setErros] = useState({});

  function handleSubmit(evento) {
    evento.preventDefault();                          // impede o recarregamento da página (SPA!)

    const errosEncontrados = validarBusca({ termo, limite });
    setErros(errosEncontrados);
    if (Object.keys(errosEncontrados).length > 0) return;   // não envia se houver erro

    const [ordenarPor, ordem] = ordenacao ? ordenacao.split(':') : ['', ''];
    buscarVeiculos({ termo: termo.trim(), ordenarPor, ordem, limite });
  }

  return (
    <form className="row g-3 align-items-start" onSubmit={handleSubmit} noValidate>
      <div className="col-md-5">
        <label htmlFor="termo" className="form-label">Termo de busca *</label>
        <input
          id="termo"
          type="text"
          className={`form-control ${erros.termo ? 'is-invalid' : ''}`}
          placeholder="ex.: car, motorcycle, electric"
          value={termo}
          onChange={(e) => setTermo(e.target.value)}
        />
        {erros.termo && <div className="invalid-feedback">{erros.termo}</div>}
      </div>

      <div className="col-md-3">
        <label htmlFor="ordenacao" className="form-label">Ordenar por</label>
        <select
          id="ordenacao"
          className="form-select"
          value={ordenacao}
          onChange={(e) => setOrdenacao(e.target.value)}
        >
          <option value="">Relevância</option>
          <option value="price:asc">Menor preço</option>
          <option value="price:desc">Maior preço</option>
          <option value="title:asc">Nome (A–Z)</option>
        </select>
      </div>

      <div className="col-md-2">
        <label htmlFor="limite" className="form-label">Resultados</label>
        <input
          id="limite"
          type="number"
          min="1"
          max="30"
          className={`form-control ${erros.limite ? 'is-invalid' : ''}`}
          value={limite}
          onChange={(e) => setLimite(Number(e.target.value))}
        />
        {erros.limite && <div className="invalid-feedback">{erros.limite}</div>}
      </div>

      <div className="col-md-2 d-grid">
        <label className="form-label invisible">Buscar</label>
        <button type="submit" className="btn btn-primary" disabled={carregando}>
          {carregando ? 'Buscando...' : 'Buscar'}
        </button>
      </div>
    </form>
  );
}

export default FormBusca;

Pontos-chave:

  • evento.preventDefault(): sem ele, o <form> faria o comportamento padrão do HTML (recarregar a página), quebrando a SPA.
  • noValidate: desliga os balões de validação nativos do navegador, para que as nossas mensagens (com Bootstrap is-invalid + invalid-feedback) sejam exibidas de forma consistente.
  • Validação antes do envio: se validarBusca encontrar erros, a função retorna sem chamar a API — economizando uma requisição inútil e dando retorno imediato ao usuário.
  • Botão desabilitado enquanto carregando for true: evita cliques repetidos e requisições duplicadas.

5.11.6 Passo 6 — Lista de resultados com os quatro estados (e erros depois do envio)

// src/components/ListaResultados.jsx
import { useEffect } from 'react';
import { useVeiculos } from '../contexts/VeiculosContext.jsx';
import CardVeiculo from './CardVeiculo.jsx';

function ListaResultados() {
  const { produtos, total, carregando, erro, ultimaBusca, carregarVeiculos } = useVeiculos();

  // Carga inicial: executa uma vez, quando o componente aparece
  useEffect(() => {
    const controlador = new AbortController();
    carregarVeiculos(controlador.signal);
    return () => controlador.abort();

  // Estado 1 — carregando
  if (carregando) {
    return (
      <div className="text-center my-5">
        <div className="spinner-border" role="status" aria-label="Carregando" />
      </div>
    );
  }

  // Estado 2 — erro (mensagem vinda DEPOIS do envio: HTTP ou rede)
  if (erro) {
    return (
      <div className="alert alert-danger my-4" role="alert">
        <strong>Não foi possível concluir a busca.</strong> {erro}
      </div>
    );
  }

  // Estado 3 — vazio
  if (produtos.length === 0) {
    return (
      <div className="alert alert-warning my-4">
        Nenhum veículo encontrado{ultimaBusca ? ` para "${ultimaBusca}"` : ''}.
      </div>
    );
  }

  // Estado 4 — sucesso
  return (
    <section className="my-4">
      <p className="text-muted">
        {ultimaBusca
          ? `Exibindo ${produtos.length} de ${total} resultado(s) para "${ultimaBusca}".`
          : `Destaques da categoria veículos (${total} no total).`}
      </p>
      <div className="row row-cols-1 row-cols-sm-2 row-cols-lg-3 g-3">
        {produtos.map((veiculo) => (
          <div className="col" key={veiculo.id}>
            <CardVeiculo veiculo={veiculo} />
          </div>

      </div>
    </section>
  );
}

      </div>
    </div>
  );
}

Dados vindos de API podem vir incompletos (um produto sem brand ou sem imagem). Por isso usamos renderização condicional (&&) e o operador ?? para valores padrão — a interface não deve “quebrar” por causa de um campo ausente.

5.11.8 Passo 8 — Formulário de cadastro: enviando JSON com POST

Este formulário combina tudo: useEffect para carregar as categorias do <select>, validação antes do envio, POST com corpo JSON, e mensagens de sucesso ou de erro depois do envio.

// src/components/FormCadastro.jsx
import { useEffect, useState } from 'react';
import { useVeiculos } from '../contexts/VeiculosContext.jsx';

const VAZIO = { title: '', brand: '', price: '', category: 'vehicle' };

function validarCadastro(dados) {
  const erros = {};
  if (dados.title.trim().length < 3) erros.title = 'O modelo deve ter pelo menos 3 caracteres.';
  if (dados.brand.trim() === '') erros.brand = 'Informe a marca.';
  const preco = Number(dados.price);
  if (dados.price === '' || Number.isNaN(preco) || preco <= 0) {
    erros.price = 'Informe um preço maior que zero.';
  }
  if (!dados.category) erros.category = 'Selecione uma categoria.';
  return erros;
}

function FormCadastro() {
  const { cadastrarVeiculo, listarCategorias } = useVeiculos();

  const [dados, setDados] = useState(VAZIO);
  const [erros, setErros] = useState({});
  const [categorias, setCategorias] = useState([]);
  const [enviando, setEnviando] = useState(false);
  const [erroEnvio, setErroEnvio] = useState(null);   // erro DEPOIS do envio
  const [sucesso, setSucesso] = useState(null);

  // GET das categorias quando o formulário aparece
  useEffect(() => {
    const controlador = new AbortController();
    listarCategorias(controlador.signal)
      .then(setCategorias)
      .catch((e) => {
        if (e.name !== 'AbortError') setErroEnvio(`Categorias indisponíveis: ${e.message}`);
      });
    return () => controlador.abort();
  }, [listarCategorias]);

  // Um único handler para todos os campos, usando o atributo "name"
  function handleChange(evento) {
    const { name, value } = evento.target;
    setDados((anterior) => ({ ...anterior, [name]: value }));
  }

  async function handleSubmit(evento) {
    evento.preventDefault();
    setSucesso(null);
    setErroEnvio(null);

    // 1. Validação ANTES do envio
    const errosEncontrados = validarCadastro(dados);
    setErros(errosEncontrados);
    if (Object.keys(errosEncontrados).length > 0) return;

    // 2. Envio (POST com JSON)
    setEnviando(true);
    try {
      const criado = await cadastrarVeiculo({
        title: dados.title.trim(),
        brand: dados.brand.trim(),
        price: Number(dados.price),          // envia número, não string
        category: dados.category,
      });
      // 3a. Sucesso DEPOIS do envio
      setSucesso(`Veículo "${criado.title}" cadastrado com o id ${criado.id}.`);
      setDados(VAZIO);
    } catch (erro) {
      // 3b. Erro DEPOIS do envio (resposta 4xx/5xx ou falha de rede)
      setErroEnvio(erro.message);
    } finally {
      setEnviando(false);
    }
  }

  // Função auxiliar para não repetir as classes de validação
  const classe = (campo, base = 'form-control') => `${base} ${erros[campo] ? 'is-invalid' : ''}`;

  return (
    <form className="card card-body my-4" onSubmit={handleSubmit} noValidate>
      <h2 className="h5">Cadastrar veículo</h2>

      {sucesso && <div className="alert alert-success">{sucesso}</div>}
      {erroEnvio && <div className="alert alert-danger">{erroEnvio}</div>}

      <div className="row g-3">
        <div className="col-md-4">
          <label htmlFor="title" className="form-label">Modelo *</label>
          <input id="title" name="title" className={classe('title')}
                 value={dados.title} onChange={handleChange} />
          {erros.title && <div className="invalid-feedback">{erros.title}</div>}
        </div>

        <div className="col-md-3">
          <label htmlFor="brand" className="form-label">Marca *</label>
          <input id="brand" name="brand" className={classe('brand')}
                 value={dados.brand} onChange={handleChange} />
          {erros.brand && <div className="invalid-feedback">{erros.brand}</div>}
        </div>

        <div className="col-md-2">
          <label htmlFor="price" className="form-label">Preço (US$) *</label>
          <input id="price" name="price" type="number" min="0" step="0.01"
                 className={classe('price')} value={dados.price} onChange={handleChange} />
          {erros.price && <div className="invalid-feedback">{erros.price}</div>}
        </div>

        <div className="col-md-3">
          <label htmlFor="category" className="form-label">Categoria *</label>
          <select id="category" name="category" className={classe('category', 'form-select')}
                  value={dados.category} onChange={handleChange}>
            <option value="">Selecione...</option>
            {categorias.map((c) => <option key={c} value={c}>{c}</option>)}
          </select>
          {erros.category && <div className="invalid-feedback">{erros.category}</div>}
        </div>
      </div>

      <button type="submit" className="btn btn-success mt-3 align-self-start" disabled={enviando}>
        {enviando ? 'Enviando...' : 'Cadastrar'}
      </button>
    </form>
  );
}

export default FormCadastro;

Como a DummyJSON só simula a gravação, o veículo cadastrado aparece no topo da lista porque o reducer o adiciona ao estado local (ação VEICULO_ADICIONADO). Se a página for recarregada, ele não estará mais lá. Com uma API real (como a do Projeto 2), o dado seria persistido no servidor.

5.11.10 Passo 10 — Testar e depurar com o DevTools

Com npm run dev rodando, abra http://localhost:5173, pressione F12 e use as abas abaixo:

  1. Network (Rede) → filtre por Fetch/XHR. Ao abrir a página, deve aparecer a requisição para category/vehicle (e a de category-list). Clique nela e confira:
    • Headers: a URL completa, o método e o status (200).
    • Payload (no POST): o JSON que foi enviado.
    • Preview/Response: o JSON que foi recebido.
  2. Busca válida: digite car, escolha “Menor preço” e clique em Buscar. Na aba Network, confira que a URL contém ?q=car&limit=10&...&sortBy=price&order=asc — são os parâmetros enviados à API.

  4. Resultado vazio: busque por xyzxyz. Deve aparecer o alerta amarelo “Nenhum veículo encontrado”.
  5. Erro depois do envio (rede): na aba Network, mude No throttling para Offline e faça uma busca. Deve aparecer o alerta vermelho “Não foi possível conectar à API…”. Volte para No throttling.
  6. Erro depois do envio (HTTP): altere temporariamente VITE_API_URL no .env para https://dummyjson.com/rota-inexistente, reinicie o servidor e observe a mensagem de erro com o status 404. Desfaça a alteração.

5.12 Mensagens de validação: antes e depois do envio

O Projeto 1 exige dois momentos de retorno ao usuário. Eles têm naturezas diferentes e ambos são necessários:

Table 5.11: Validação antes e depois do envio à API
Antes do envio (cliente) Depois do envio (servidor/rede)
Quem verifica O próprio componente React A API (ou a infraestrutura de rede)
Exemplos Campo obrigatório vazio; texto curto demais; número fora do intervalo; e-mail em formato inválido Status 400/404/422/500; mensagem de erro no corpo JSON; sem internet; bloqueio de CORS; busca sem resultados
Onde aparece no código Função validar...() chamada no handleSubmit, antes da requisição if (!resposta.ok) + try/catch na função requisicao e no componente
Objetivo Retorno imediato e evitar requisições inúteis Informar o que realmente aconteceu no servidor
Pode ser dispensado? Não — melhora a experiência Nunca — o cliente pode ser burlado; o servidor é a validação definitiva

Boas práticas para as mensagens:

  • Mostre a mensagem perto do campo com problema (e não apenas um alert() genérico).
  • Diga como resolver (“Digite pelo menos 2 caracteres”), e não só que há erro (“Campo inválido”).
  • Limpe as mensagens antigas a cada novo envio (setErroEnvio(null), setSucesso(null)).
  • Nunca exiba objetos de erro crus ([object Object]) ou stack traces para o usuário.

Bibliotecas de formulário: react-hook-form, Formik e Yup (todas na lista de sugestões do projeto) automatizam exatamente a parte de “validação antes do envio”: registro dos campos, regras (obrigatório, tamanho mínimo, formato) e mensagens por campo. Entender a versão manual deste capítulo torna muito mais fácil usar qualquer uma delas.

5.13 Gerando o pacote de deployment e publicando

Durante o desenvolvimento, o Vite serve os arquivos diretamente do src/. Para publicar, é preciso gerar o pacote de produção: arquivos HTML, CSS e JS otimizados e minificados.

npm run preview   # serve a pasta dist/ localmente para conferir (http://localhost:4173)

A pasta dist/ contém apenas arquivos estáticos — ela pode ser hospedada em qualquer servidor web (Apache, Nginx) ou em serviços gratuitos de hospedagem estática.

5.14 Versionamento incremental com Git

O Projeto 1 avalia a atualização incremental do código no Git e a participação de cada integrante. Um único commit com o projeto inteiro não demonstra isso. Uma sequência saudável para o exemplo deste capítulo seria:

git commit -m "chore: cria projeto Vite + React e instala Bootstrap"
git commit -m "feat: adiciona VeiculosContext com reducer e carga inicial da API"
git commit -m "feat: implementa busca com parâmetros (q, sortBy, order, limit)"
git commit -m "feat: valida campos obrigatórios da busca antes do envio"
git commit -m "feat: exibe estados de carregando, erro e vazio na lista"
git commit -m "feat: adiciona formulário de cadastro com POST em JSON"
git commit -m "build: configura base do Vite e script de deploy no GitHub Pages"
git commit -m "docs: documenta API, hook, biblioteca e ferramentas (incluindo IA) no README"

Dicas:

  • Cada integrante deve commitar com a própria conta, na parte pela qual é responsável.
  • Faça commits pequenos, com mensagens que dizem o que mudou.
  • Inclua no .gitignore a pasta node_modules/ e a pasta dist/ (o Vite já cria esse arquivo).
  • O README.md deve documentar a API escolhida, o hook, a biblioteca externa, as ferramentas usadas (inclusive de IA) e o link da aplicação publicada.

HTTP Protocolo de requisição/resposta da Web; cada mensagem tem linha inicial, cabeçalhos e corpo opcional.
